# Frame studio (authoring)

## Summary

- **What it does:** An unlisted page at `/studio` where a pack author uploads story/post overlays (png, jpg, or jpeg), places photo slots and one optional mood face on a live canvas, orders those layers Photoshop-style, and exports a zip to commit into `loggoo_asset`.
- **Primary user journey:** Open `/studio` → enter localized names (id is derived from English) → pick story or post → upload the overlay (or remove it to swap in another; slots and mood stay) → switch the canvas to `draw slot` and drag a hole (it snaps back to `select`) → adjust slots → optionally add, move, resize, or rotate one mood face for that aspect → reorder rows in the layers panel to decide what paints on top → repeat for the other aspect → export zip → unzip into `loggoo_asset/frames/<id>/` and paste the catalog snippet into `catalog.json`.
- **Key states:** empty canvas; draft restored from a previous visit (toast + `start over` to discard); overlay loaded; canvas mode `select` / `draw slot`; frame, photo slot, or mood selected (one at a time; the selected layer lifts above the stack so its handles stay reachable); optional mood face absent/present/selected; export validation (error toast + invalid field ring); catalog snippet filled after a successful export (success toast).
- **Status:** in progress on `loggoo_web`. The app fetch/renderer is a separate change in `loggoo_app`.

## Implementation

- **Architecture & data flow:** Static Astro page, client-only editor. Photo geometry uses canvas fractions. Schema v3 stores an optional mood placement per aspect as normalized `x`/`y`, fixed-design-canvas `sizeDp`, and rotation, plus `layers`: the bottom-to-top paint order of `{kind:'overlay'}`, `{kind:'photo', photo}`, and `{kind:'mood'}`. Text binds always paint above every layer and are not in `layers`. In the editor each aspect keeps `layers: string[]` (`'overlay'`, `'mood'`, or a slot id); the canvas maps that order to inline `z-index` (10 + position, selected layer 100). `sanitizeLayers` guarantees the export has the overlay once, every photo once, and the mood iff present — missing entries fall to the bottom in the default order (photos, overlay, mood). Export builds `manifest.json` plus the selected images into an uncompressed zip. GitHub Pages on `loggoo_asset` is the host the app fetches; this page never talks to GitHub.
- **Key files:**
  - `src/pages/studio.astro` — unlisted studio shell, not linked from `Nav`.
  - `src/scripts/frame-studio.ts` — pointer canvas: draw, drag, resize, aspect switch.
  - `src/scripts/frame-pack.ts` — schema v3, sanitization, catalog snippet, zip STORE writer.
  - `src/scripts/frame-draft.ts` — one-record IndexedDB draft (get / put / delete) so overlays (`File`s) survive a reload.
- **Notable decisions & trade-offs:** The canvas stacks exactly as the manifest will: a new photo is inserted just under the overlay (right for png overlays with transparent holes), the mood goes on top, and the author can move any row with ▲ ▼. The selected layer lifts above the whole stack with a translucent fill so its handles stay grabbable; deselect to preview the real order. `.frame__slots` / `.frame__mood` are `pointer-events: none` containers with no stacking context, so every `.slot`, the overlay `<img>`, and `.mood-face` sort directly against each other by inline `z-index`. Two canvas modes avoid the old ambiguity between "click the frame" and "drag to draw": `select` picks the frame / slot / mood (Backspace removes whichever is selected; clicking the stage outside the canvas clears the selection), `draw slot` rubber-bands one hole and returns to `select`. Schema bumped to v3; `loggoo_app` must read `layers`. Note the app's pre-v3 fixed order was overlay → photos → mood (overlay as background), so for v1/v2 packs the app keeps that legacy order — see `loggoo_app/docs/superpowers/plans/2026-09-19-frame-pack-layers.md`. Each aspect has at most one mood placement and previews a representative Loggoo-drawn face; the actual face comes from `FrameDay.topMood`. No GitHub token lives in the browser — publish remains a human git commit. Text binds are in the schema but are not authorable yet.
- **Session, history, zoom:** Every committed change (`commit()` at each mutation site: drag end, add/remove slot or mood, layer reorder, overlay upload/remove, photo index) pushes a `Snapshot` — `JSON.stringify(layouts)` plus the two overlay `File` refs — onto a 100-step history; identical snapshots are skipped, so plain clicks do not pollute undo. ⌘/Ctrl Z undoes, ⇧⌘/Ctrl Z or Ctrl Y redoes (text fields keep the browser's own undo). Object URLs are cached per `File` and never revoked, because history and the draft keep old files reachable. The same state plus names, premium, aspect, and icon is debounced 400 ms into IndexedDB from `renderSlots()` / `renderOverlay()`; on mount `restoreDraft()` puts it back and toasts the saved time. `start over` (confirm dialog) clears the draft and resets everything. ⌘/Ctrl + / − / 0, and ⌘/Ctrl + wheel or trackpad pinch (zooming about the cursor by adjusting the stage scroll), zoom the canvas 0.5×–4× by scaling the frame's container-query size through `--zoom`; the stage scrolls, and `margin: auto` keeps the frame centred while it fits and start-aligned once it overflows.
- **Rail icon spec:** square png/jpg, ≥128px (rejected otherwise, with the actual size in the toast), 256px recommended; the studio decodes the file to check and shows the size under the picker. The app draws it at 40dp (120px on 3x screens). The fallback icon is now 256px. Draw it like the built-in `ic_frame_*` vectors: 34-unit viewBox, `#4A3728` 1.7 strokes, pastel fills at 35–55% — `loggoo_app/.../composeResources/drawable/ic_frame_dump.xml` is the reference.
- **Aspect seeding:** switching to an aspect with no slots and no mood copies the other aspect's slots, mood, and layer order (new slot ids), rescaling `y`/`h` by the aspect height ratio so each box keeps its dp size; the author then nudges instead of redrawing.
- **Tests:** `npm run build` / `npx tsc --noEmit`. No browser E2E in v1.
- **Follow-ups:** `loggoo_app` renderer honors `layers` (schema v3); draggable text binds; Figma plugin that dumps slot JSON; load an existing pack back onto the canvas; drag-to-reorder rows.

- 2026-08-29: Added `/studio` with a drag canvas for photo slots and zip export aimed at `loggoo_asset`.
