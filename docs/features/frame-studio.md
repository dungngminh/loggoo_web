# Frame studio (authoring)

## Summary

- **What it does:** A page at `/studio` (linked from the landing nav, still `noindex`) where a pack author optionally uploads story/post overlays (png, jpg, or jpeg), optionally sets a background (solid colour or full-bleed image), places photo slots, one optional mood face, one optional Loggoo logo tile, and one optional note text box on a live canvas, orders the stacked layers Photoshop-style, and exports a zip to commit into `loggoo_asset`.
- **Primary user journey:** Open `/studio` → enter localized names (id is derived from English) → pick story or post → upload the overlay (or remove it to swap in another; slots and mood stay) → switch the canvas to `draw slot` and drag a hole (it snaps back to `select`) → adjust slots → optionally pick a background colour or image → optionally add, move, resize, or rotate one mood face and one loggoo icon for that aspect → optionally add the note text, drag it, pull its right edge to set the wrap width, and pick font / size / colour / max lines / align in the inspector → reorder rows in the layers panel to decide what paints on top → repeat for the other aspect → export zip → unzip into `loggoo_asset/frames/<id>/` and paste the catalog snippet into `catalog.json`.
- **Key states:** empty canvas; draft restored from a previous visit (toast + `start over` to discard); overlay loaded; canvas mode `select` / `draw slot`; frame, background, photo slot, mood, logo, or note text selected (one at a time; the selected layer lifts above the stack so its handles stay reachable); optional mood face / logo tile / note text absent/present/selected; background none / colour / image; export validation (error toast + invalid field ring; every aspect needs at least one photo slot, overlays are optional on v4 and required on v2 / v3); catalog snippet filled after a successful export (success toast).
- **Schema target:** a `schema · app version` select (v4 · app 1.5.1 and up, v3 · app 1.5.0, v2 · app 1.4.1 and below) picks which pack schema the zip and catalog snippet use. The studio hides what the chosen schema never had: v3 drops the background and Loggoo logo blocks, the text box handles (width, rotate) and the max lines / align fields; v2 also drops the ▲ ▼ layer order. Export strips those fields from the manifest too, so a v4 draft exported as v2/v3 loses them rather than leaking unknown keys. The choice is saved with the draft.
- **Status:** in progress on `loggoo_web`. The app fetch/renderer is a separate change in `loggoo_app`.

## Implementation

- **Architecture & data flow:** Static Astro page, client-only editor. Photo geometry uses canvas fractions. Schema v4 stores per aspect: an optional `background` (`{kind:'color', color:'#RRGGBB'}` or `{kind:'image', file:'story_bg.png'}`, always painted first, never in `layers`); optional `mood` and `logo` placements sharing the `MoodPlacement` shape (normalized `x`/`y`, fixed-design-canvas `sizeDp`, rotation) — the logo adds `style`: `tile` (mark on the dark `#211915` brand tile, the app's `LoggooLogoTile`), `dark` (bare `LoggooBrandMark` in `onSurface #4A3728`, for light artwork), or `light` (bare mark in `#FBF6F0`, for dark artwork); the moment dot is always primary `#F6B393`; `texts` (a `note` bind with `x`, `y`, `w` wrap width as a fraction, `rotation` −45..45 about the box centre, `font`, `sizeSp`, `color`, `maxLines` 1–20, `align` start/center/end — the app wraps inside `w` and cuts with an ellipsis); and `layers`: the bottom-to-top paint order of `{kind:'overlay'}`, `{kind:'photo', photo}`, `{kind:'mood'}`, and `{kind:'logo'}`. Text binds always paint above every layer and are not in `layers`. In the editor each aspect keeps `layers: string[]` (`'overlay'`, `'mood'`, `'logo'`, or a slot id); the canvas maps that order to inline `z-index` (background 1, layers 10 + position, texts 90, selected 100). Backgrounds live beside overlays as `Record<Aspect, {kind:'color',color} | {kind:'image',file: File} | null>` because image backgrounds are Files; they ride along in every undo snapshot and the draft. `sanitizeLayers` guarantees the export has every photo once, and the overlay / mood / logo iff present (`overlay` is omitted from the aspect when no file was uploaded) — missing entries fall to the bottom in the default order (photos, overlay, mood, logo), unknown kinds are dropped; `sanitizeText` clamps `w`/`x`, size, lines, and falls back to `#4A3728` for a bad colour. Export builds `manifest.json` plus the selected images (overlays when present, icon, and `story_bg.<ext>` / `post_bg.<ext>` when the background is an image) into an uncompressed zip. GitHub Pages on `loggoo_asset` is the host the app fetches; this page never talks to GitHub.
- **Key files:**
  - `src/pages/studio.astro` — studio shell; `src/components/Nav.astro` links it as `studio`.
  - `src/scripts/frame-studio.ts` — pointer canvas: draw, drag, resize, stickers (mood / logo share one code path), note text box, background, aspect switch.
  - `src/scripts/frame-pack.ts` — schema v4, sanitization, catalog snippet, zip STORE writer.
  - `src/scripts/frame-draft.ts` — one-record IndexedDB draft (get / put / delete) so overlays (`File`s) survive a reload.
- **Notable decisions & trade-offs:** The canvas stacks exactly as the manifest will: a new photo is inserted just under the overlay (right for png overlays with transparent holes), the mood goes on top, and the author can move any row with ▲ ▼. The selected layer lifts above the whole stack with a translucent fill so its handles stay grabbable; deselect to preview the real order. `.frame__slots` / `.frame__mood` are `pointer-events: none` containers with no stacking context, so every `.slot`, the overlay `<img>`, and `.mood-face` sort directly against each other by inline `z-index`. Two canvas modes avoid the old ambiguity between "click the frame" and "drag to draw": `select` picks the frame / slot / mood (Backspace removes whichever is selected; clicking the stage outside the canvas clears the selection), `draw slot` rubber-bands one hole and returns to `select`. Schema bumped to v4; `loggoo_app` must read `background`, `logo`, and the text `w` / `maxLines` / `align` fields, and should skip v4 packs until it does (its catalog parser already skips unknown schemas). Note the app's pre-v3 fixed order was overlay → photos → mood (overlay as background), so for v1/v2 packs the app keeps that legacy order — see `loggoo_app/docs/superpowers/plans/2026-09-19-frame-pack-layers.md`. Each aspect has at most one mood placement and previews a representative Loggoo-drawn face; the actual face comes from `FrameDay.topMood`. The logo sticker previews the mark from `Logo.astro` in the chosen style (a three-way `tile` / `dark mark` / `light mark` toggle under its block) and reuses every mood interaction (`Sticker = 'mood' | 'logo'`), so both are one code path. The note text box previews a fixed sample sentence at `sizeSp × 100cqw / 360` (the `.frame` is an inline-size container so sp scales with zoom), wraps with `-webkit-line-clamp: maxLines`, and only its width is draggable (right-edge handle) — height follows the line cap, matching the app; the top knob rotates it like a slot, measuring the angle from the rendered box's centre. Only the `note` bind is authorable; `title` / `date` / `mood` texts stay unexposed until the app needs them. The background block offers a colour picker and an image picker; picking one replaces the other; the colour `input` event previews live and only `change` commits an undo step. The layers panel pins note text rows on top and a background row at the bottom (no ▲ ▼); selecting the background row and pressing Backspace removes it. No GitHub token lives in the browser — publish remains a human git commit.
- **Slot size readout & ratio lock:** a selected slot's corner badge reads `W×Hdp · rot° · rcorner` on the app's fixed design canvas (360dp wide, 640 / 450dp tall) and updates live while moving or resizing; the `draw slot` rubber band shows the same `W×Hdp` via `data-size` + `::after`. The layers row uses the same dp label. The inspector has `width · dp` / `height · dp` number inputs (commit on `change`, so the field can be cleared and retyped; resize from the top-left corner, clamped to the canvas; with the lock on, the other side follows) and a `lock aspect ratio` checkbox: the checkbox is editor-only state (not in the manifest or draft): while checked, corner handles keep the slot's ratio at drag start, following whichever axis the pointer stretched more and clamping to the canvas from the anchored corner.
- **Session, history, zoom:** Every committed change (`commit()` at each mutation site: drag end, add/remove slot or mood, layer reorder, overlay upload/remove, photo index) pushes a `Snapshot` — `JSON.stringify(layouts)` plus the two overlay `File` refs — onto a 100-step history; identical snapshots are skipped, so plain clicks do not pollute undo. ⌘/Ctrl Z undoes, ⇧⌘/Ctrl Z or Ctrl Y redoes (text fields keep the browser's own undo). Object URLs are cached per `File` and never revoked, because history and the draft keep old files reachable. The same state plus names, premium, aspect, and icon is debounced 400 ms into IndexedDB from `renderSlots()` / `renderOverlay()`; on mount `restoreDraft()` puts it back and toasts the saved time. `start over` (confirm dialog) clears the draft and resets everything. ⌘/Ctrl + / − / 0, and ⌘/Ctrl + wheel or trackpad pinch (zooming about the cursor by adjusting the stage scroll), zoom the canvas 0.5×–4× by scaling the frame's container-query size through `--zoom`; the stage scrolls, and `margin: auto` keeps the frame centred while it fits and start-aligned once it overflows.
- **Rail icon spec:** square png/jpg, ≥128px (rejected otherwise, with the actual size in the toast), 256px recommended; the studio decodes the file to check and shows the size under the picker. The app draws it at 40dp (120px on 3x screens). The fallback icon is now 256px. Draw it like the built-in `ic_frame_*` vectors: 34-unit viewBox, `#4A3728` 1.7 strokes, pastel fills at 35–55% — `loggoo_app/.../composeResources/drawable/ic_frame_dump.xml` is the reference.
- **Aspect seeding:** switching to a completely empty aspect (no slots, stickers, text, or background) copies the other aspect's slots, mood, logo, note text, background, and layer order (new ids), rescaling `y`/`h` by the aspect height ratio so each box keeps its dp size; the author then nudges instead of redrawing.
- **Tests:** `npm run build` / `npx tsc --noEmit`. A throwaway jsdom smoke script (not committed) exercised add/remove of stickers, note text, background colour/image, Backspace, undo, and aspect seeding. No browser E2E in v1.
- **Follow-ups:** `loggoo_app` renderer honors schema v4 (`background`, `logo`, text `w` / `maxLines` / `align`); `title` / `date` / `mood` text binds; Figma plugin that dumps slot JSON; load an existing pack back onto the canvas; drag-to-reorder rows.
